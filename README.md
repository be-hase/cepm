# cepm

**C**hrome **E**xtension **P**ackage **M**anager — keep git-distributed, unpacked
Chrome extensions up to date automatically.

Many teams distribute internal Chrome extensions as git repositories (the
Chrome Web Store is not an option for internal tools): everyone clones the
repo and loads it via *chrome://extensions* → "Load unpacked". The painful
part is staying current — you have to remember to `git pull` **and** hit the
reload button for every extension. cepm automates both.

```console
$ cepm install git@github.example.com:team/internal-extensions.git
```

After a one-time "Load unpacked" per extension, updates flow automatically:
while Chrome is running, cepm pulls every 30 minutes and reloads the
extensions whose files changed. `cepm update` does the same on demand.

## How it works

```
Chrome ── cepm helper extension (loaded once, generated by cepm setup)
             │  native messaging (stdio, launched & managed by Chrome)
             ▼
        cepm native host ── periodic git pull ── reload changed extensions
             ▲                                    (management.setEnabled off/on
             │  unix socket                        = re-read from disk)
        cepm CLI (install / update / list / doctor)
```

- No daemons to configure: Chrome itself starts and stops the native host.
- If Chrome is closed, `cepm update` still pulls; unpacked extensions are
  re-read from disk on the next Chrome launch anyway.
- One repository can contain any number of extensions (any directory with a
  `manifest.json` is picked up automatically).
- Upgrades of cepm itself propagate hands-free: Chrome launches the host via
  a stable launcher script (`~/.cepm/bin/cepm-host`) that every cepm
  invocation keeps pointed at the current binary (Homebrew, `go install`,
  mise shims, or plain file replacement all work), and on connect the host
  refreshes the helper extension's files and asks it to reload itself when
  they are outdated.

## Install

```console
$ go install github.com/be-hase/cepm/cmd/cepm@latest   # or grab a release binary
$ cepm setup
$ # one-time: chrome://extensions → Developer mode → "Load unpacked" → ~/.cepm/helper
$ cepm doctor        # verify everything is green
```

macOS is supported today (Linux/Windows: the OS-specific paths are stubbed
out and contributions are welcome).

## Usage

```console
$ cepm install <git-url>          # clone + register (then load unpacked once)
$ cepm update                     # pull everything, reload what changed
$ cepm list                       # what's registered, and is it loaded?
$ cepm reload                     # reload without pulling (local hacking)
$ cepm uninstall <name>           # unregister + delete the clone
$ cepm doctor                     # diagnose setup / connectivity
$ cepm id <path>                  # print the extension ID for a directory
```

### Tracking release tags instead of a branch

If a repo's default branch carries unstable work-in-progress, follow release
tags instead — cepm then only ever checks out the newest matching tag
(compared as semver):

```console
$ cepm install <git-url> --track tag --tag-pattern "v*"
```

### Repository-side configuration (`cepm.toml`, optional)

Extension authors can commit a `cepm.toml` at the repo root so that consumers
get the right behavior with a plain `cepm install <url>`:

```toml
# Explicit extension directories (skips auto-detection):
extensions = ["dist/sidebar", "dist/search"]

# Recommend tag tracking to consumers:
track = "tag"
tag_pattern = "v*"
```

### User configuration (`~/.cepm/config.toml`, optional)

```toml
[update]
interval = "30m"   # auto-update cadence while Chrome runs (min "1m")
auto     = true    # set false to only update via "cepm update"

[git]
stash_dirty = false  # stash/pop around pulls when a clone has local edits
```

By default a repo with local modifications is skipped (with a warning) so
your experiments are never clobbered; `cepm update --force` stashes and
restores them around the pull.

## Notes & limitations

- Loading an extension the first time is always manual — Chrome has no API
  for "load unpacked". cepm prints the exact directories to load, and only
  for brand-new extensions.
- The helper extension needs the `management` permission (to toggle other
  extensions), `nativeMessaging`, and `alarms`. It never touches page data.
- Everything lives under `~/.cepm/` (clones, state, logs at
  `~/.cepm/logs/host.log`).
